# Lessons about words on a page

Read this when writing or changing what a page or a paper says.

- **Plain words, the user's own first.** Plain words on the page, the lender's words in the paper. A code or an id never reaches the screen. (D-UX-200, D-UX-345)
- **One word for one idea, everywhere.** "Provisional" only when figures may still change. (D-UX-88)
- **A status names what it counts** ("All questions answered"). A word set beside a verdict is read as part of it. (OR11a, 29-10-2026)
- **An error says what is wrong and how to put it right.**
- **Short sentences help**: about 25 words is where a reader on a phone starts to lose the thread. A guide, not a count to pass.
- **Show, never claim.** Each quality is shown by what the paper really has. "Ready to take to your lender", never "accepted", never a bank's name. Nothing is called sanctioned before it is. No invented quotes. (D-UX-124, D-UX-155, D-UX-194, D-UX-103)
- **A claim on a page must be true and stay true.** "We set no cookies" stops being true the day an ad script is added: hold such a line with a test. (D-BIZ-16, D-BIZ-22)
- **A notice's trigger tests what the page or file shows**, not what the data holds; and a notice shows only where the thing it is about shows. (TM1, D-BIZ-05)
- **Voice on web headings; papers stay formal.** (D-UX-103)
- **An AI may draft words from the user's own inputs, marked as a draft**; never a figure, never a claim a new business cannot have. (D-AI-01, D-AI-02; a hard line)
- **With Rahul, name a setting as their screen shows it.**
- **Say it once.** What one place shows, another in view beside it does not repeat. (D-UX-237)
