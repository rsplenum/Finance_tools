# Lessons

What this project has learned, kept by topic so that a session reads only the part its work touches.

A lesson says what happened and what we took from it. It is there to make the next piece of work better, never to limit it. When a lesson stands in the way of a better result, set it aside and say so in one line. Only the hard lines at the top of `CLAUDE.md` do not bend: money, law and privacy.

| Working on | Read |
| --- | --- |
| Anything Rahul will look at: a page, a flow, a paper, a film | `rahul.md` (Rahul's own words) |
| A page's layout, look or flow | `design.md` |
| The words on a page | `words.md` |
| A check, a test, or a finding from a review | `checks.md` |
| A session's cost, tools and handoff | `sessions.md` |
| Money maths | the `money-maths-checks` skill |
| A PDF, Excel or Word file | the `lender-documents` skill |
| A trap in one file or tool | grep `docs/GOTCHAS.md` for the file's name |
| Why something was decided | grep `docs/DECISIONS.md` by id or word; older entries are in `docs/archive/DECISIONS-RETIRED.md` |

No file here is read by every session. Nothing here is checked by a script.

## Adding a lesson

- One entry in its topic file: what happened, what we learned, when it applies. Give the date and the row, so the story can be found.
- If an entry already says it, sharpen that entry. Never a second copy.
- A lesson becomes a check only when a machine can tell right from wrong **and** it guards money, law, privacy, accessibility or a flow that breaks for the user. A matter of taste is never a check.
- Take a lesson out when it no longer holds. A lesson that proved wrong is corrected in place.

The files these replaced are in `docs/archive/` (REFORM1, 11-11-2026; `docs/REFORM1-LEDGER.md` has the verdict on each).
