# Lessons about sessions: cost, tools and handing off

Read this when a session feels slow or costly, or when setting one up.

## Where the tokens go

Tokens are for building, and for checking that the new thing works. Reading rules and keeping books is overhead: keep it small.

- **Grep first, but read whole what the task is about.** "Never read a large file whole" taught sessions to skim, and a deep dive was done on three files of twelve (11-11-2026). When Rahul asks for a deep dive, list what will be walked and read, cover all of it, and say plainly what was left out.
- **Say what you take each link or attachment for** before building on it. Read what Rahul attaches in full.
- Put independent commands in one step. Fetch many pages through one script that prints only what is needed.
- Every large tool result is re-read at each later step until a compaction. A long task in an old conversation costs more than the same task in a new one; after a break of over an hour the cache has lapsed.
- Name a site's hosts and check they are open before reading it; never try a blocked host. (D-TECH-35)
- A search summary or a model's summary of a page is a lead, never a source for a figure. (D-DATA-20)
- After changing a tool's setting, confirm its effect in the logs before stating it as fact.

## One row, one session

- One deliverable a session, with a size named before it starts; the deliverable is the real thing, rough but real.
- One session per row; the branch pushed first is the claim. A hook guards it, so there is nothing to remember. (D-TECH-62, D-TECH-70)
- Before a `git reset` or `checkout -B`, look at `git log origin/<branch>` and `git status`.
- Work goes in the repo where its subject lives: films are the studio's.

## Records

- `docs/HANDOFF.md` says where things stand and what is next. Keep it short: it is read whole.
- `docs/DECISIONS.md` is a dated log to grep. A line goes in when Rahul decides something, or when a choice about money, law or the product's shape would otherwise be made twice. A change to the code is not a decision: the commit holds it.
- A lesson goes in its topic file here (see `README.md`).

## Gears

Think fully on money maths, a red check whose cause is not plain, and a design choice. Think briefly on docs and regenerated files. Rahul switches on the highest effort; a skill cannot.
